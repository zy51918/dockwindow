# DockWindow 产品需求文档（PRD）

- **产品名称**：DockWindow
- **文档版本**：1.1
- **文档日期**：2026-09-07
- **产品形态**：Windows 托盘工具
- **目标平台**：Windows 10/11，x64

## 1. 产品概述

DockWindow 是一个 Windows 托盘工具，用于将普通桌面窗口停靠到屏幕边缘并自动隐藏。用户将窗口拖到屏幕左侧、右侧或顶部边缘，松开鼠标后，窗口自动滑出屏幕，仅保留一条 4 像素的可见条。鼠标移入可见条时，窗口滑回原停靠位置；鼠标离开窗口一段时间后，窗口再次隐藏。

产品同时提供基于**程序名**的 enable/disable 规则列表，用于控制哪些程序可以被 DockWindow 管理。规则通过 exe 同目录下的 `dockwindow.json` 配置文件维护。

## 2. 产品目标

1. 提供简单、低干扰的窗口边缘自动隐藏体验。
2. 保留窗口原有尺寸和用户停靠位置。
3. 支持鼠标快速唤回隐藏窗口。
4. 通过托盘菜单提供全局启用、全部还原和退出能力。
5. 允许用户按程序名配置可控制范围，不影响未配置时的默认行为。
6. 在窗口关闭、配置变更、应用退出等场景下，不遗留隐藏位置或置顶状态。

## 3. 用户场景

### 3.1 自动停靠

用户将记事本、计算器或其他普通窗口拖至屏幕左边缘、右边缘或顶部边缘，松开鼠标后窗口自动隐藏，只留下 4 像素可见条。

### 3.2 鼠标唤回

用户将鼠标移动到可见条上，窗口在约 150 毫秒内滑回停靠位置。鼠标进入窗口后，窗口保持显示；鼠标离开窗口约 300 毫秒后，窗口重新隐藏。

### 3.3 忘记停靠

用户将已经停靠的窗口从屏幕边缘拖离，DockWindow 停止管理该窗口，窗口保持在用户拖到的位置，并清除 DockWindow 设置的置顶状态。

### 3.4 程序规则控制

用户希望只控制 Notepad：

```json
{
  "rules": [
    "enable notepad",
    "disable all"
  ]
}
```

用户希望禁止 Notepad，但允许其他程序：

```json
{
  "rules": [
    "disable notepad",
    "enable all"
  ]
}
```

## 4. 功能需求

### FR-01：窗口边缘识别

系统必须监听顶层窗口的移动/调整大小结束事件，并识别窗口是否触碰以下边缘：

- 左边缘：窗口左侧距离工作区左侧不超过 8 像素。
- 右边缘：窗口右侧距离工作区右侧不超过 8 像素。
- 顶部边缘：窗口顶部距离工作区顶部不超过 8 像素。
- 其他位置：不执行停靠。

当窗口同时触碰多个边缘时，优先级固定为：

```text
Left > Right > Top
```

底部边缘不支持，以避免与任务栏发生冲突。

### FR-02：窗口停靠与隐藏

满足停靠条件的窗口必须：

1. 保留原始宽度和高度。
2. 将窗口边缘吸附到工作区边界。
3. 使用约 150 毫秒的 ease-out cubic 动画滑出屏幕。
4. 左、右边缘隐藏时保留 4 像素宽的可见条。
5. 顶部边缘隐藏时保留 4 像素高的可见条。
6. 隐藏后不得抢占前台焦点。
7. 窗口被唤回时可以可靠地显示在非置顶窗口之上。

### FR-03：窗口唤回与再次隐藏

- 鼠标进入可见条后，窗口必须进入唤回状态。
- 鼠标进入完整窗口区域后，窗口保持可见。
- 鼠标离开完整窗口区域持续约 300 毫秒后，窗口再次隐藏。
- 鼠标轮询周期为约 50 毫秒。
- 窗口关闭或 HWND 失效时，系统必须自动移除该窗口，不得导致应用崩溃。

### FR-04：可停靠窗口过滤

窗口必须同时满足以下条件，才允许进入 DockWindow 管理列表：

- 窗口有效且可见。
- 不是 Shell 窗口。
- 没有 owner 窗口，是普通顶层窗口。
- 样式包含 `WS_CAPTION`。
- 样式不包含 `WS_EX_TOOLWINDOW`。
- 未被 DWM cloak。
- 程序规则策略允许该窗口所属进程。

程序名比较对象为进程的可执行文件名，例如 `notepad.exe`。无法解析进程名时，系统采用默认放行策略，保持未配置时的兼容行为。

### FR-05：enable/disable 规则列表

#### 规则格式

配置文件名为 `dockwindow.json`，位置为应用 exe 所在目录。配置结构如下：

```json
{
  "rules": [
    "enable notepad",
    "disable all"
  ]
}
```

每个规则由两个部分组成：

```text
<action> <process-prefix>
```

其中：

- `action` 只能是 `enable` 或 `disable`，不区分大小写。
- `process-prefix` 是程序名匹配前缀，不区分大小写。
- `all` 是特殊目标，匹配所有程序。
- `enable notepad` 匹配 `notepad.exe`，也会匹配以 `notepad` 开头的其他程序名。

#### 规则优先级

规则按数组顺序从上到下进行判断，**第一个匹配的规则立即生效**，后续规则不再判断。

例如：

```json
{
  "rules": [
    "enable notepad",
    "disable all"
  ]
}
```

结果为：

- `notepad.exe`：允许停靠。
- `calc.exe`：被 `disable all` 禁止停靠。

以下配置中，`disable all` 会先匹配，因此后面的规则不会生效：

```json
{
  "rules": [
    "disable all",
    "enable notepad"
  ]
}
```

#### 默认行为

以下情况必须默认允许程序停靠：

- `dockwindow.json` 不存在。
- 文件无法读取。
- JSON 格式无效。
- `rules` 字段不存在或为空。
- 所有规则均无效。
- 有效规则存在，但没有规则匹配当前程序。
- Windows 无法查询目标进程名。

用户如果希望形成严格白名单，必须显式添加 `disable all` 作为兜底规则。

#### 非法规则处理

单条非法规则不得导致整个应用退出。系统应跳过该规则，并通过诊断日志记录原因。以下内容属于非法规则：

- 空字符串。
- 缺少 action 或程序名前缀。
- action 不是 `enable` 或 `disable`。
- 包含多余字段，无法解析为两个部分。

### FR-06：规则加载与重载

- 应用启动时读取一次 `dockwindow.json`。
- 托盘菜单必须提供 **Reload rules** 操作。
- 用户修改配置文件后，选择 **Reload rules** 即可应用新规则。
- 不要求使用 `FileSystemWatcher` 自动监听文件变化。
- 重载后已停靠但不再被允许的窗口必须先恢复到原停靠位置，再从管理列表移除。
- 重载后重新被允许的窗口不自动追溯停靠，只有下一次符合条件的窗口移动事件才会进入管理。

### FR-07：托盘菜单

右键托盘图标必须提供以下菜单项：

1. **Enabled**：全局启用/禁用。
   - 取消勾选后，所有已停靠窗口立即恢复。
   - 取消勾选后不再处理新的窗口移动和鼠标事件。
   - 重新勾选后不自动重新停靠此前已恢复的窗口。
2. **Reload rules**：重新读取配置文件并应用规则。
3. **Restore all**：恢复所有已停靠窗口并清空管理列表。
4. **Quit**：恢复所有窗口、释放资源并退出进程。

## 5. 非功能需求

### NFR-01：性能

- 鼠标轮询周期约为 50 毫秒。
- 无规则时不应为每次窗口移动额外查询进程信息。
- 窗口动画周期约为 15 毫秒。
- 规则判断必须是线性顺序扫描，规则列表规模较小时不应造成可感知延迟。

### NFR-02：稳定性

- 所有 Win32 调用必须检查返回值。
- 目标窗口关闭、进程退出或权限不足时，应用不得崩溃。
- 进程查询打开的句柄必须在所有路径上正确关闭。
- 应用退出时不得遗留窗口置顶状态。

### NFR-03：兼容性

- 目标框架为 .NET 8 `net8.0-windows`。
- 使用 WinForms 托盘图标和消息循环。
- 支持 PerMonitorV2 DPI 感知。
- 支持多显示器，并使用对应显示器的工作区而非完整屏幕区域。
- 不引入第三方原生依赖。

### NFR-04：可维护性

- 几何计算、动画计算和规则匹配应保持为可单元测试的纯逻辑。
- Win32 调用集中在 `Win32.cs` 中。
- 配置解析集中在 `RulesConfig.cs` 中。
- 规则匹配逻辑集中在 `DockRules.cs` 中。

## 6. 产品状态与状态转换

单个停靠窗口包含以下状态：

```text
Hidden   ：窗口已隐藏，仅保留可见条。
Peeking   ：鼠标进入可见条，窗口正在或已经滑回。
Visible   ：窗口完整显示，等待鼠标离开延迟结束。
```

状态转换：

```text
Hidden -> Peeking  鼠标进入可见条
Peeking -> Visible 鼠标进入完整窗口区域
Visible -> Hidden   鼠标离开窗口持续约 300 毫秒
任意状态 -> 移除    窗口关闭、被拖离边缘或规则变为禁止
```

## 7. 验收标准

### AC-01：基础停靠

- 将普通窗口拖至左边缘，窗口隐藏并留下 4 像素条。
- 将普通窗口拖至右边缘，窗口隐藏并留下 4 像素条。
- 将普通窗口拖至顶部边缘，窗口隐藏并留下 4 像素条。
- 将窗口拖至底部边缘，窗口不被停靠。

### AC-02：唤回和隐藏

- 鼠标移入可见条，窗口滑回原位置。
- 鼠标进入窗口后移开，约 300 毫秒后窗口再次隐藏。
- 拖动已停靠窗口离开边缘后，窗口不再受管理。

### AC-03：规则匹配

- 不存在配置文件时，普通窗口仍可正常停靠。
- `enable notepad` 允许 `notepad.exe`。
- 程序名前缀匹配不区分大小写。
- `enable all` 允许所有程序。
- `disable all` 禁止所有程序。
- 规则按从上到下的顺序执行，首个匹配规则优先。
- 未匹配任何规则时默认允许。
- 非法规则被忽略，不影响其他有效规则。

### AC-04：规则重载

- 修改 `dockwindow.json` 后点击 **Reload rules**，新规则立即用于后续窗口移动。
- 已停靠但被新规则禁止的窗口恢复到原位并停止管理。
- 配置重新允许某程序后，不自动追溯停靠已恢复的窗口。

### AC-05：全局开关与退出

- 取消 **Enabled** 后所有已停靠窗口恢复。
- 取消 **Enabled** 后新窗口不会被停靠。
- 点击 **Restore all** 后所有窗口恢复。
- 点击 **Quit** 后所有窗口恢复，进程正常退出。

### AC-06：异常与多显示器

- 关闭隐藏窗口后应用不崩溃。
- 无法读取目标进程名时应用继续运行并按默认放行处理。
- 在多显示器之间移动窗口时，窗口使用新显示器工作区重新计算停靠位置。
- 配置 JSON 损坏时应用继续运行，并按默认放行处理。

## 8. 范围边界

### 本版本包含

- 左、右、顶部边缘停靠。
- 4 像素可见条。
- 鼠标轮询唤回。
- 多显示器工作区适配。
- 全局 Enabled 开关。
- Restore all 和 Quit。
- 基于进程 exe 名称的 enable/disable 规则列表。
- 手动 Reload rules。

### 本版本不包含

- 底部边缘停靠。
- 配置编辑 UI。
- 自动文件监听和自动重载。
- 快捷键。
- 安装程序。
- 按窗口标题匹配。
- 按完整路径、用户、显示器或窗口实例做规则匹配。
- 应用重启后恢复之前的停靠状态。

## 9. 技术映射

| 模块 | 职责 |
|---|---|
| `TrayContext` | 托盘菜单、应用生命周期和全局 Enabled 开关 |
| `WindowEventHook` | 监听窗口移动/调整大小结束事件，并切回 UI 线程 |
| `MousePoller` | 周期性读取鼠标位置 |
| `DockManager` | 管理停靠窗口注册表，协调规则、边缘判定和状态变更 |
| `DockedWindow` | 管理单个窗口的隐藏、唤回和动画状态机 |
| `DockRules` | 解析并执行 enable/disable 规则 |
| `RulesConfig` | 读取和解析 `dockwindow.json` |
| `EdgeDetector` | 纯几何边缘识别和隐藏矩形计算 |
| `Animation` | 纯数学动画插值 |
| `Win32` | 集中封装 Windows API 调用 |

## 10. 测试要求

### 自动化测试

xUnit 测试至少覆盖：

- 边缘阈值和角落优先级。
- 隐藏矩形和可见条矩形计算。
- 动画缓动和插值。
- 空规则默认放行。
- `enable`、`disable` 和 `all` 规则。
- 程序名大小写不敏感前缀匹配。
- 首个匹配规则优先。
- 未匹配规则时的默认行为。
- 非法规则忽略。

### 人工冒烟测试

1. 拖动 Notepad 到左、右、顶部边缘。
2. 鼠标移入可见条并验证唤回。
3. 鼠标离开并验证约 300 毫秒后重新隐藏。
4. 拖离边缘并验证窗口被忘记。
5. 使用 `disable all` 验证所有程序均不被停靠。
6. 使用 `enable notepad` + `disable all` 验证仅 Notepad 被停靠。
7. 使用 `disable notepad` + `enable all` 验证除 Notepad 外均可停靠。
8. 修改配置并点击 **Reload rules**，验证规则即时生效。
9. 关闭隐藏窗口、切换多显示器、关闭 Enabled 并退出应用。
